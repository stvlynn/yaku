# Article context and automatic terminology

## Scope and evidence

This is a read-only clean-room specification for the context/terminology preparation that underlies Translation Comparison. It is not an implementation or an original-extension runtime acceptance. No proprietary script was executed, no account/service endpoint was contacted, and no product, build, model profile or experiment script was changed. The only authored file in this investigation is this document. [Translation editing research](translation-editing.md) establishes the comparison journey and its separate limits.

## What the reference actually distinguishes

| Mechanism                         | Evidence-backed behavior                                                                                                          | What it does not establish                                                                           |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Article context preparation       | Before translation, obtain article theme/context, extracted terms and potentially a style guide; inject those into later requests | Not equivalent to passing a user glossary, title alone or one neighboring sentence                   |
| Incremental smart term extraction | Translation batches can report new terms actually used; accepted session terms inform subsequent batches                          | Not the same acquisition path as the article-summary service; not automatically a permanent glossary |
| Custom user glossary              | User-supplied mappings and URL scopes; optional glossary names act as semantic context labels                                     | Labels are not deterministic URL matching and do not prove AI term extraction                        |
| AI Expert                         | Installed/custom prompt strategy with manual/automatic selection and language/site/service conditions                             | A persona prompt is not an article summary or a second model                                         |
| Comparison                        | Run real contextual and baseline translations for matching source units and display differences                                   | A source-versus-translation view or user-glossary-only contrast is not the full AI context feature   |

The official [prompt guide](https://immersivetranslate.com/en/docs/prompts/) defines title, summary and terminology variables; it states that the latter two are supplied by proprietary extraction services for eligible members. The public [expert repository](https://github.com/immersive-translate/prompts) describes experts as prompt configurations and exposes separate single/batch/subtitle fields. These sources describe supported contracts, not a successful session observed here.

## Static source acquisition and preparation

1. **Title is separate metadata.** The inspected service-config builder uses the original title when present, otherwise the document title, and supplies the hostname. URL-based exclusions can suppress this metadata. C 1650321 and 1688976. A title is not evidence that the entire article was read.
2. **Article/body selection precedes the prepass.** The article parser obtains distinct body/article nodes through its existing body rules. When both are found and context is enabled, it sends a prefix of the selected body's `innerText`. Packaged body rules specify a minimum text length of 800, a 20,000-character context request length and a 4,000 ms service timeout. C 2359700-2361994; D `generalRule.bodyRule`. These are reference defaults, not recommended local-model token limits. The prefix is not proof of whole-article coverage, hidden/unloaded-page acquisition or universal extraction accuracy.
3. **The preparation request is not ordinary translation.** A bounded function checks service prompt capability, the context toggle, entitlement/token state and nonempty body before a request candidate to `transai/summary-context`. Its body contains target language, detected source language and selected body text; response consumers read theme, terms and optional style guidance. C 1662350-1663992. This is a static endpoint/payload observation only: no credentials were read, request issued, backend model identified or successful response observed.
4. **Snapshots and reuse exist.** C 1591385 constructs frozen generation/body-fingerprint/target-language snapshot containers and a frozen parsed-term map containing theme, raw/parsed terms and optional style guide. C 1662304-1663992 uses a memory map keyed by body fingerprint and target. Generation checks prevent an earlier preparation result from replacing the current generation. The inspected preparation path can reuse a previous context under an explicit condition. This does not prove durable storage, eviction, cross-tab reuse, or that service/model/expert changes are included in every cache path.
5. **Only relevant terms enter each translation context.** C 1591904 filters the prepared term map against current source texts, while keeping theme/style information. C 1674157 injects available context fields; absent fields remove corresponding prompt fragments. Title/summary/terms and subtitle variants remain separate template inputs. A configured provider prompt must actually consume those fields for the toggle to matter.
6. **Preparation has an article lifetime.** C 2342974 manages a preparation promise, current translation identity and invalidation. The static path catches preparation failures; it does not establish visible failure disclosure or cancellation of the remote computation. A clean-room design must specify those outcomes independently.

The package enables context for some membership services and disables it for the generic OpenAI default. Its AI Expert feature flag is distinct from the context toggle. Locale text describes a theme/writing-style prepass and eligibility restrictions; the General-expert restriction is also advertised. Domain presets and matching rules can change effective service settings, so one default flag does not prove availability for all services/sites.

## Incremental terminology and ambiguity are additional features

The static terminology session at C 1263544-1265840 is bound to translation/service/target identity. It registers static glossary sources, accepts only nonempty source/target pairs, deduplicates normalized sources, keeps first accepted session entries and caps accepted terms at 200 by default. Matching dynamic terms are added for later source batches without overriding static mappings. Its exclusive execution path supplies a reason to translate terminology-dependent batches sequentially rather than in arbitrary completion order.

The packaged enhanced-batch term instruction asks for a small bounded set of newly discovered terms whose target was actually used in that response, with optional reliable short-name aliases. This instruction is a desired model contract, not proof every reported term is correct. C 1602713 accepts reported candidates, records accepted/filtered statistics and marks new terms as AI-extracted/unsaved. The surrounding locale workflow offers review, occurrence details, explicit save to a chosen glossary, highlighting and separate hide/disable controls. Visibility of highlights is not equivalent to extraction/application being enabled.

Eligibility checks at C 1775411-1775809 include service batch capability, recommended/enhanced protocol mode, membership, URL matching, user enablement and visit-level disablement. The package's general batch policy contains `enableArticleTerminology:false`; this one static flag does not settle effective runtime eligibility. An AO3-oriented preset advertises context but is itself disabled by default. Locale copy calls smart extraction experimental on AO3. These facts do not justify claiming universal extraction, reliable term quality, or that any service can emit the same protocol.

The official [advanced glossary documentation](https://immersivetranslate.com/en/docs/advanced/#translating-the-same-term-differently-by-context) distinguishes optional semantic glossary-name labels from deterministic URL scopes. For example, different senses of an ambiguous word can be presented with domain labels and article context. The existing deterministic one-target glossary map alone cannot represent competing labeled senses. A future ambiguity feature must keep candidate senses separate and cannot silently reinterpret existing glossary priority.

The inspected comparison baseline does **not** blanket-clear manual glossary configuration. At C 2344114, the article baseline copies the request, removes the context snapshot/source, automatic terminology session/document context/observer, and marks its sentences outside article context. Its context copy changes the cache flag while retaining service/rule configuration. At C 1679797, the provider comparison passes the same request to the two translation calls, changing only the optional prepared context argument. C 1687911 still supplies the request's glossary to `handleGlossaries`; C 1696939 copies those terms first and adds prepared-context terms only for source keys not already supplied. These scoped constructors retain manual terms while suppressing the automatic context/session path. This is bounded static evidence, not a claim about every service or an observed network pair.

The provider's service environment still contains the title in both calls. Therefore its no-prepared-context arm can retain title metadata, manual glossary, expert/service prompt and structural protocol. It is not necessarily a title-free or all-terminology-free baseline. A local comparison should state exactly which components differ. A scientifically controlled primary contrast keeps title, manual terms, model/languages, domain strategy and format instructions fixed while changing generated theme/style/automatic terms. A separate raw-title/neighbor-source ablation or all-terminology contrast must be labeled separately.

**Structural format context is never the semantic ablation variable.** Preserve the same source text/unit IDs, inline marker grammar, code/URL protection, output parser, source/target hints and integrity requirements in both arms. An overloaded `TranslationRequest.context` may currently carry codec instructions; deleting that entire field would change the task and invalidate the comparison. Introduce distinct typed format-instruction and semantic-context inputs before offering this comparison. The inspected baseline retains sentence text/request options; no constructor here establishes that codec-format instructions should be removed. [Editing research](translation-editing.md) remains the reference for its UI journey and unknown runtime behavior.

## Clean-room local contract

The following is a proposed implementation contract, not an assertion of observed reference runtime semantics.

### Build an inspectable article snapshot

Reuse source extraction and inline protection rather than scraping rendered translations. The snapshot should contain an article/document-unit identity, source revision, deterministic title/headings, ordered original text units and their stable IDs, source-language hints, an extraction coverage descriptor and source fingerprint. Keep navigation, forms/editors, hidden text, scripts/styles, code/formula payloads and generated translation UI out of prose context. Preserve links/code as protected source assets rather than asking the model to regenerate them. Dynamic changes must create a new source revision; an old result cannot attach to a new route/document unit.

Source acquisition is restricted to currently available authorized document content. Reading a visible article does not authorize hidden-page scraping, pagination fetching, iframe escape or private provider endpoints. Existing per-frame injection can prepare that frame's own content. Reader/PDF/EPUB adapters should supply explicit document units through the same typed boundary, not fake a web-page title or merge unrelated chapters. If only a prefix/sample is available, expose that coverage; do not call it a whole-article analysis.

### Keep deterministic metadata, generated context and user instructions distinct

A context snapshot should distinguish extracted title/headings/raw neighboring source, generated theme/summary, optional style guidance, explicit user terms, generated session terms, and domain/sense candidates. Include provenance, source revision, generator/model/prompt version and preparation status. Do not store everything in an opaque context string or label static metadata as AI-generated.

All source/title/domain content is data, including instructions embedded in an article. Application policy and marker grammar remain outside that data. User instructions and explicit terminology have stated precedence; generated terms must not override user glossary spelling. Language/script hints remain independent of domain context. Output is parsed and rendered as data through the existing strict inline policy.

### Provide an explicit control and truthful lifecycle

The user enables article context for the current scope and can inspect the prepared summary/terms, cancel preparation and clear session data. Show preparation, ready, partial, failed and cancelled states when relevant. A generation failure must not silently present baseline translation as context-enhanced. An explicitly chosen baseline continuation is a separate outcome. Changing target, expert/prompt, source revision, glossary or relevant domain policy invalidates dependent work. Hiding term highlights alone does not stop extraction/application; disabling extraction does.

Default generated context/session terms should remain local to the reading session unless the user explicitly saves terms. Cache identity must include content revision, title/metadata, languages, model/quantization and prompt versions, explicit glossary revision and enabled context components. Comparison arms need separate keys; baseline cannot reuse a context-enhanced output. Reuse of preparation is allowed only for an identical validated snapshot. The reference's observed body/target map is not a sufficient independent cache design.

### Make automatic term adoption accountable

Before accepting a generated pair, verify nonempty values, that the source occurs in the permitted source text, and that the proposed target occurs in its actual translated output. Record source/target occurrence evidence, batch identity and rejection reason. Literal occurrence is necessary but not semantic proof; proper-name aliasing and generic-word rejection still need quality evaluation. Preserve static/user term priority, deduplicate and bound session growth. Promote accepted terms only after the corresponding translation has passed integrity checks; baseline/comparison requests cannot contaminate the article's live term state.

Translation batches that depend on earlier terms need deterministic ordering. Parallel unrelated work may remain possible, but a later batch cannot acquire terms from whichever response happened to finish first. Reject malformed term protocol output rather than rendering it as translation or substituting canned data. Saving to a durable glossary is an explicit user action through the existing glossary workflow.

## What HY-MT2 can and cannot be assumed to do

The official [Hy-MT2 instructions](https://github.com/Tencent-Hunyuan/Hy-MT2#hy-mt2-translation-task-instruction-examples-chinese-english-comparison) describe terminology intervention, style, background information, delimiters and structured translation. They specify full language names, no default system prompt and an 8,192-token context. This supports testing supplied context/terms with the existing local model; it does not establish a reliable article-summary generator or bilingual term-mining agent. The packaged browser quantization/runtime still requires its own measurements.

| Requirement                                                               | HY-MT-only feasibility                                          | Evidence still needed                                                                                               |
| ------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Title/headings/ordered source acquisition                                 | Deterministic DOM/document code; no second model needed         | Extraction coverage, protected-content and revision fixtures                                                        |
| Translate with supplied background/terms/style                            | Officially documented task family                               | Actual quantized-model disambiguation, integrity and latency ablation                                               |
| Generate a faithful summary/style description                             | May be attempted with the same local generator                  | Must demonstrate task adherence, completeness and no invented facts; translation-task support alone is insufficient |
| Extract bilingual terms from actual translation                           | May be attempted with the same local generator                  | Combined versus separate-pass protocol reliability, precision, source/target grounding and subsequent consistency   |
| Domain/expert prompt and competing-sense selection                        | Prompt/data policy can stay local                               | Counterfactual domain tests and explicit ambiguity handling                                                         |
| Comparison                                                                | Two real local inference runs can provide honest paired results | Frozen source/components, separate cache keys, failure/cancellation and integrity behavior                          |
| Remote proprietary prepass, membership service, full provider acquisition | Cannot be claimed as reproduced by local prompting              | Independent local adaptation must be named and validated as such                                                    |

Do not add another model/cloud service or copy proprietary expert prompts to make an unproven capability appear complete. If HY-MT2 cannot reliably prepare summaries/terms, report that gap; deterministic title/raw context can still be offered under its accurate name. Use the loaded tokenizer/configuration to budget preparation and translation input/output, not the reference's 20,000-character prefix or a hardcoded output truncation. Long-article coverage needs an explicit chunk/aggregation design and separate validation. Derive each chunk from the loaded model context limit minus instruction/metadata/protected-token overhead and an output reserve; record which original units each chunk and aggregate represent. A hierarchical summary must be checked for lost names, facts and numbers across chunk boundaries. Reference character/term caps are observations, not local defaults.

## Concrete next experiments and implementation order

1. **Acquire fixtures before generation.** Create two contrast pairs: a finance/river article with the same sentence about reaching a bank, and music/baseball articles with the same sentence about a perfect pitch. The title/body supplies the intended sense; provide no glossary that gives away the answer. Freeze UTF-8 source, title, unit IDs and reviewed sense expectations. Add one repeated-name/acronym article and one inline-link/code/number case for subsequent gates.
2. **Separate context use from context generation.** On the four contrast articles, compare no context, title plus raw surrounding source, a human-reviewed short context, and HY-MT-generated context. This is 16 paired source translations plus four preparation attempts, not an unrelated broad corpus. Save exact prompts, raw preparation/output, tokenizer counts, source fingerprints and latency. Then compare the winning direct-source arm against an extracted theme/terms/style-guide arm with the same translation input; keep those components independently switchable rather than crediting all improvement to a glossary. Do not assume the model returns reliable JSON: record plain-text versus structured-protocol task adherence and reject invalid preparation output explicitly. If supplied context does not help, do not blame the summarizer; if reviewed context helps but generated context fails, the preparation step is the gap.
3. **Test terminology as its own mechanism.** Use the repeated-name/acronym article in three ordered batches. Compare no automatic extraction with generated grounded terms carried to later batches, holding user glossary and all other context fixed. Test separate post-translation extraction against a combined translation-plus-term protocol. Permit a deliberately preserved proper name; reject invented terms, absent source/target strings and unreliable alias splits. Measure later-batch consistency and accepted/rejected candidate precision, not merely term count.
4. **Measure ambiguity/domain policy.** Swap only the article/domain context while keeping the ambiguous source identical; the intended sense should change appropriately. Separately test two explicitly labeled user-supplied senses without changing deterministic URL-based glossary behavior. Add an unrelated-title negative control to detect over-conditioning.
5. **Run the integrity gate.** Combine the winning context/term approach with existing inline markers, protected code/URLs/formulas, source hints, Traditional output and number 731 in a small fixture. Evaluate source/asset equality and semantic completeness independently. Adversarial source text must not become an application instruction. Do not retest unrelated image/document corpora.
6. **Implement only measured contracts.** Introduce typed article/context snapshot data at the entity boundary; place source acquisition/protection reuse below feature slices. A context-preparation feature receives the unified local generator and source snapshots by injection. The content orchestrator connects it to page translation/comparison through public APIs; one feature must not import a peer feature's internals. Keep generated-term state and user-glossary storage separate.
7. **Then integrate paired comparison.** Freeze the source and prepared context snapshot for both arms. Keep codec/format instructions intact, separate them from semantic context, and state whether title and user glossary are held constant; prevent baseline output/terms from entering the enhanced run's cache/session. Render actual paired results/differences with one-sided failures and cancellation visible. Two different strings alone are not proof of improvement, and duplicating one result into both sides is not a comparison.
8. **Finish lifecycle browser acceptance.** Toggle/cancel during preparation and between dependent batches; change target, glossary, expert and SPA article; test iframe/document units, late results, cache reuse/invalidation and session clearing. Use one verified cached model profile serially and record actual executed build identity. No model/profile run was performed for this research.

The upstream [IFMTBench](https://github.com/Tencent-Hunyuan/Hy-MT2/tree/main/IFMTBench) separates rule-checkable glossary/layout/code constraints from judged style/background disambiguation. Follow that distinction: local exact checks plus human semantic review are sufficient for this small gate; do not silently introduce its optional external LLM judge. Passing user-glossary compliance alone must never be reported as full AI article-context parity.

### Minimum experiment report

Report baseline versus direct original title/nearby source versus extracted theme/terms/style guide as distinct arms. For every arm, record article coverage/unit IDs, actual input/context/output token counts, preparation-call count, cold/warm timings, queue time, tokenization time and translation time. Measure prefill separately only if the runtime exposes a defensible measurement; otherwise report time to first token as a named proxy with its included overhead, rather than claiming it is pure prefill. Include end-to-end latency so an extra preparation pass is not hidden behind a fast later translation. Assess sense accuracy and cross-batch term consistency alongside number/clause preservation and extraction hallucination rates. If contextual output is unchanged, preserve that result; do not manufacture a diff or assume no context was consumed. No model or profile was used in this read-only investigation.
