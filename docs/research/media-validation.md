# Media and document validation matrix

This matrix separates implementation, small-fixture verification and unverified production coverage. It does not claim complete equivalence with the reference extension.

## Implemented workflows

The [full reference inventory](feature-parity.md) includes 214 advertised subtitle platforms. This implementation does not mark that list as supported. Each injected frame operates on its own document; a context-menu command targets the supplied frame ID. Caption visibility must already be enabled by the platform/user. No microphone capture, ASR, cloud caption generation or automatic call interaction is implemented.

DOM exports are explicitly named `observed-captions`; VTT includes a NOTE explaining approximate timing and incomplete coverage. Meeting timestamps are relative to observation, and video DOM timestamps use observed player time. Native tracks retain actual source cue times. Appearance changes must retain already captured history, including captions that have left the DOM. Language or glossary changes retranslate retained source history; cue IDs remain stable across refreshes. Focused unit regressions cover those requirements.

## DOCX story traversal and compatibility

DOCX discovery now follows the package `_rels/.rels` internal `officeDocument` relationship rather than assuming `word/document.xml`. Its main-part relationships select internal header, footer, footnote, endnote and comment parts using the Transitional or Strict relationship URI family. Selected parts must exist, have the expected WordprocessingML content type from `[Content_Types].xml`, and have the matching root element in a recognized Word namespace. Targets resolve relative to the relationship source, with above-root traversal and external URI targets excluded. Missing identities, invalid selected types/roots or dangling selected internal relationships fail explicitly; there is no filename fallback. Unknown and external relationships are retained without being followed or fetched. Only selected XML parts are reserialized; unrelated uncompressed part bytes and relationship/manifest bytes remain unchanged, although the ZIP container itself is rebuilt.

One paragraph processor handles both Transitional and Strict. Text is joined only from runs owned by the nearest paragraph, so tables and `w:txbxContent` paragraphs are independent from their enclosing paragraph. Bilingual copies omit note-reference and note-number markers along with existing identifier/drawing exclusions, retaining the original references once. Allocation of translated text to original run formatting remains approximate.

Markup compatibility is preserved rather than preprocessed for a guessed Word version. All `mc:Choice` and `mc:Fallback` branches remain in the file; each branch's Word paragraphs are translated independently, including distinct text in alternate textbox representations. Identical alternatives may therefore require repeated translation requests and appear repeatedly in the raw preview; a consuming Word reader chooses the applicable representation. No branch is silently discarded, and no target application's namespace capabilities are invented. Bilingual outer-paragraph copies do not duplicate drawings/textboxes; the original textbox containers receive their own translated paragraphs.

Official references: [package relationships](https://learn.microsoft.com/en-us/office/open-xml/general/how-to-create-a-package), [WordprocessingML stories](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document), [textbox content](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.textboxcontent?view=openxml-3.0.1), and [markup compatibility](https://learn.microsoft.com/en-us/office/open-xml/general/introduction-to-markup-compatibility). These define structure, not evidence that an exported file has been opened in every Word version.

The focused round-trip suite uses OPC relationship/content-type fixtures and covers all selected story families, arbitrary main/story paths, relative targets, both namespace families, unrelated/external preservation, distinct Choice/Fallback textboxes, bilingual footnote/endnote markers, invalid identities/types and package-escaping targets. These are deterministic structural tests, not model-quality or Microsoft Word/LibreOffice rendering acceptance. `altChunk` imports, glossary/building-block stories, chart/SmartArt text, embedded subdocuments, generated field behavior and every tracked-revision/MC construct remain backlog. No all-format-parity claim follows from this bounded repair.

## Explicit page-image batch verification

The batch starts only after an explicit user command, observes loaded near-viewport images in the main/article/body scope, and serializes OCR/model work. It does not scroll the page or probe lazy-loader attributes. Stop cancels pending work while retaining completed overlays; Restore also restores owned image attributes. Preference changes stop an active batch. Each background fetch verifies the requested URL against the current native DOM in the authorized frame, with omitted credentials. Session authorization survives service-worker suspension and is revoked on restore/tab closure.

`tests/page-images-batch.test.ts` covers lazy discovery, duplicate sources, dynamic source replacement, cancellation, preference changes, small images, blank-text classification and late-response guards. The opt-in `scripts/experiments/reader-batch-real-model.mjs` exercised actual Chrome, packaged OCR and cached HY-MT2 against an original synthetic HTTP reader. Three images translated into Chinese, including a 200-by-100 image; a blank image counted as skipped. The offscreen lazy image remained original until scrolling near it. Between images, CDP stopped the actual background worker; its replacement loaded stored authorization and completed the next translation. A URL absent from the page was rejected without a network request. Restore returned original picture/source/img attributes exactly and revoked the grant. No page errors were observed.

The experiment uses a real loopback HTTP page and image server because browser route interception does not intercept extension service-worker fetches and a synthetic public-origin page encounters Chrome local-network policy. It dispatches the existing registered context-menu handler through the debugger, rather than automating the native operating-system menu. The executed background source is compared with the built source before validation: reused Chrome profiles were empirically found to retain an older installed service-worker body despite rebuilt files. A fresh fixture profile seeded with verified model data was used for the passing run; this is not a fresh-download claim.

Local evidence: `reader-batch-real-model-result.json`, `reader-first-translated.png`, `reader-lazy-restart-translated.png`, `reader-restored.png`, and three `reader-*.translated.png` files under `.workspace/qa/`. The screenshot visibly contains the synthetic fixture and translated/queued/without-text progress. This verifies the generic DOM reader workflow, not every manga service or the reference extension's advertised reader list. Read-only inspection of the public [Pepper&Carrot episode](https://www.peppercarrot.com/en/webcomic/ep01_Potion-of-Flight.html) showed ordinary episode image elements alongside icons/thumbnails; no comic artwork was copied into the fixture or product. Lazy-load design follows [browser-native lazy loading](https://web.dev/articles/browser-level-image-lazy-loading) and [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API); these references establish browser behavior rather than production-site acceptance.

## Caption media identity and export scope

Native cues and observed player captions now belong to a media-node/resource scope. YouTube video IDs and Netflix watch IDs take priority over transport URLs; seeking, playlist/time parameters and transport blob churn on the same known video do not reset history. Generic players use the loaded/declared resource URL, ignoring a temporal fragment; unrelated document query/hash changes do not reset them. Observed meeting history uses the adapter and room pathname, retaining query-only account/UI changes. Inactive source scopes are excluded from transcript/export, and late results check the current scope before touching the DOM. These are conservative fixture-tested identity rules, not an undocumented universal SPA navigation detector.

`pretranslate` and `exportSubtitles` accept an optional `media` element, and `getTranscript(media?)` filters an explicit player. A real context-menu event captures its media target for one action; detachment, changed navigation/resource identity, or a subsequent context menu invalidates that selection. Ambiguous multi-player global commands ask the user to choose a video rather than merging players. Meeting-room exports select the observed room captions instead of participant video tracks. No production entrypoint or test-only product action is added.

`tests/video-subtitles-scope.test.ts` covers two-player export/pretranslation isolation, generic seek/query retention, a same-node resource switch with late output, YouTube ID navigation with time/playlist/blob changes, meeting room changes, and meeting participant videos. The full focused subtitle suite contains 24 passing fixtures; TypeScript checking passed. This scope repair has been exercised through real Chrome fixtures but not authenticated production playback. Provider video IDs and seeking are distinct concepts in the official [YouTube player API](https://developers.google.com/youtube/iframe_api_reference); browser resource identity and loading lifecycle are documented by [HTMLMediaElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement). These sources inform the identity policy; the public DOM selectors retain their existing inferred/observed status.

The native-cue identity regression additionally covers script-created cues that survive a resource change: unchanged cue text/timing remains retired even through a refresh; a host-provided text or timing change can reuse the object. Native cue retiming replaces exact exported bounds instead of merging old bounds (observed utterances still merge their observed intervals). This repair was reproduced as a failing deterministic fixture before the guard was added.

A real Chrome/HY-MT2 scoped-media run passed two actual native players with distinct Chinese translations, separate selected-player VTT exports, trusted pointer context events, consumed/outside-video selection refusal with no extra download, byte-identical exports after seeking/query changes, and YouTube-ID navigation that excluded old history and rejected a pending retired cue. This fixture used the official [MDN CC0 flower video](https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.webm), stored only in ignored local research; `YAKU_VIDEO_FIXTURE` can select a local copy. The experiment remains `scripts/experiments/scoped-media-real-model.mjs`. Actual menu item selection is debugger-dispatched after the real pointer context event; native operating-system menu selection is not claimed.

The complete fixed-build scoped Chrome run passed, with `completed: true` in `scoped-media-real-model-result.json`. Generic document query/hash changes retained byte-identical exports. An actual resource switch retired its unchanged script-created cue and refused export without creating a download. New `Thank you.`/`谢谢。` captions excluded the previous source. Retiming exported exact 0.200-0.800 second bounds; a third resource kept the unchanged cue retired until a timing-only host update reused it, then exported exact 0.300-0.600 second bounds with its real Chinese translation. No page errors occurred. The executed background SHA matched the fixed build before inference.

Evidence includes `scoped-media-real-model.png`, `scoped-media-generic-real-model.png`, per-player/source/retimed VTT files, and the completed JSON under `.workspace/qa/`. Both screenshots were inspected. Expected refusal feedback from the negative case may remain visible alongside a subsequent successful export. The script's unique-tab lookup compares normalized URLs without relying on fragment-containing Chrome URL patterns. These are local synthetic playback fixtures with actual native video/cue/browser/model behavior, not authenticated platform sessions.
