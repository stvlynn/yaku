# Native caption track research

Native track selection/loading is separate from provider-specific subtitle acquisition. The shipped reference advertises source/target tracks, pretranslation and manual-track preference; static `generalRule.subtitleRule` contains `preTranslation`, `humanPreferred`, `aiSubtitlePreferred` and `autoSwitchSubtitleWithSameLanguage`. These are observed configuration/labels, not proof of a browser-standard ASR provenance field or working acquisition on all advertised platforms. No reference implementation is copied.

## Standards and observed Chrome behavior

The HTML standard distinguishes disabled, hidden and showing text tracks. Disabled tracks expose `cues === null`; hidden tracks participate in cue processing without native display. Enabling a declared external track can start its normal resource-loading algorithm. Automatic native selection respects an existing showing candidate before considering preferences/default. `default` is not an unconditional selection override. [WHATWG text-track model](https://html.spec.whatwg.org/multipage/media.html#text-track-model), [text-track API](https://html.spec.whatwg.org/multipage/media.html#text-track-api).

`TextTrack.language`/`HTMLTrackElement.srclang` describe the declared BCP 47 track language. `label` is human-facing text. Standard `kind` distinguishes subtitles/captions/descriptions/chapters/metadata; it does not identify human authorship versus ASR. Do not infer ASR from strings such as "auto-generated". `HTMLTrackElement.readyState` distinguishes not loaded/loading/loaded/error; a mode alone does not establish successful cue acquisition. [MDN track properties](https://developer.mozilla.org/en-US/docs/Web/API/TextTrack), [srclang](https://developer.mozilla.org/en-US/docs/Web/API/HTMLTrackElement/srclang), [readyState](https://developer.mozilla.org/en-US/docs/Web/API/HTMLTrackElement/readyState).

The isolated `scripts/experiments/native-track-behavior.mjs` ran actual Chrome 157 against a local HTTP video and English/French WebVTT files without the extension/model. It used the official MDN CC0 video fixture; no production account, private endpoint or provider network interception was involved. `.workspace/qa/native-track-behavior.json` records a completed run and native mode/cue/network snapshots:

| Scenario                                     | Observed result                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| No default, initially disabled tracks        | `cues === null`, readyState 0, no VTT request                             |
| Set English to hidden                        | Normal VTT request, readyState 2, cues accessible, mode hidden            |
| Set English and French showing               | Both remained showing; mode assignment did not enforce one selected track |
| Disable an already loaded French track       | readyState remained 2 while cues became null                              |
| Re-enable loaded French as hidden            | Cues returned without another VTT request                                 |
| Enable a missing VTT                         | readyState 3 and empty cues; no successful acquisition                    |
| Declared default English                     | English selected/showing and loaded in this fresh fixture                 |
| Append another default after a French choice | French stayed showing; newly appended default stayed disabled             |

The existing-choice probe also observed another failed candidate showing; the evidence records actual states rather than asserting all native scripts enforce exclusivity. The product must handle multiple active candidates and failures explicitly. Browser preferences and other engines may differ. [MDN mode behavior](https://developer.mozilla.org/en-US/docs/Web/API/TextTrack/mode) documents loading implications; actual Chrome observations are bounded to this fixture.

## Implemented native policy

Reuse a unique player-selected showing caption/subtitle track. If none is showing, a unique hidden caption/subtitle track is a candidate for players with custom caption display. Multiple active candidates must not be translated/exported together. No disabled track is enabled during automatic observation. Native controls remain the normal selection UI.

For an explicit pretranslate/export command with no active choice, a unique declared source-language match, unique default or sole eligible candidate can identify a track to acquire; ambiguous candidates require an accessible explicit choice. A temporary hidden mode can load an explicitly selected disabled track without displaying it. Restore only a mode value still owned by that operation; preserve a subsequent native-player/user change. Loading failure, cancellation, source replacement and disposal must not fall through to a different language or stale cue history.

The public surface adds `getTracks(media?)`, optional `trackId`/`acquire` command options on pretranslate/export, `getTranscript(media?, trackId?)`, and `onTrackSelectionRequired` for root integration. `chooseSubtitleTrack` is a shared feature helper used by the content entrypoint only when selection is necessary. Track IDs/history must remain separate even when languages have equal cue timestamps/text. Track URL/resource revisions must retire prior data. The actual selected track's declared language supplies its source hint rather than forcing a mismatched global preference. Global source language helps rank candidates only when the native player has no chosen track.

This native capability does not claim provider-specific fetching, full-video tracks beyond what the browser actually loads, ASR discovery/generation, or support for the reference's entire 214-platform list. Caption labels remain untrusted display data and do not become selectors, instructions or provenance claims.

## Loading and lifecycle details

Explicit acquisition temporarily sets a selected disabled track to hidden and waits for native load/error. The resource-loading deadline is 15 seconds, separate from model generation, which has no new token/time cap. The loader also checks readyState because an already completed load may precede event-listener registration. Failure is reported for that chosen resource; another language is not silently substituted. A known loaded resource can be enabled again through the browser cache. Script-created tracks have no HTMLTrackElement readiness contract and are reported as unknown until cues are available.

A hidden-mode lease is released on success, failure or cancellation. It restores only the hidden value the operation wrote, preserving a subsequent different native mode and other tracks' modes. An external write of the identical hidden value cannot be distinguished using the browser's public API; this ownership limitation is documented rather than patched through global property interception. A changed candidate/resource identity, track-list/mode change, navigation, preference refresh, media detachment and disposal abort the relevant pending choice/loading or prevent a late write. A still-pending model promise may finish internally; cancelled results cannot be inserted.

Source hints are canonicalized to supported model codes from BCP 47 metadata: regional English/French tags reduce to supported base languages, Traditional Chinese script/region preserves `zh-Hant`, and an explicitly declared Hans script wins over a regional convention. Invalid/unsupported metadata uses the configured supported source hint or auto; labels never become source hints. Generic Chinese acquisition can match a single declared Chinese script candidate without pretending generic Chinese means Simplified. An existing showing player choice outranks the global source preference.

When valid observed DOM captions already exist and native tracks are off, the normal command continues exporting observed captions. It does not silently replace a usable observed source with a dormant native track; explicit `trackId` or `acquire:true` can request native acquisition. Track resource revisions and per-track history keep native language streams separate. No new persisted settings or always-visible selection controls were added.

## Verification

`tests/video-subtitles-tracks.test.ts` adds 19 native-focused cases covering player priority, two showing/hidden choices, exact per-track export, disabled/default loading, readiness/failure, timeout, source-hint canonicalization, user/peer mode changes, callback cancellation, disposal, track URL replacement and preservation of a host-edited cue when its player is removed. The complete focused subtitle suite has 43 passing tests. Existing scope/history/DOM fixtures remain green.

`scripts/experiments/native-track-acquisition.mjs` bundles the current source into a local Vite fixture without rebuilding the extension. Actual Chrome fetched no disabled track initially; an explicit French source match fetched only French VTT, exported only French with the normalized `fr` hint, and restored disabled mode. An explicit English ID loaded/exported English independently. Two showing same-label tracks invoked the accessible picker; choosing French exported only French. Initial focus was a button, Escape removed the dialog and restored the invoker, and navigation aborted the pending dialog. No browser/page/controller errors were recorded. Evidence is `.workspace/qa/native-track-acquisition.json` with `completed:true` and its screenshot.

That browser fixture uses deterministic injected translation to isolate track/browser behavior. It does not claim new HY-MT2, extension-CSP or authenticated-provider acquisition acceptance. The combined installed-extension/model check is recorded below with its own executed-source preflight. The picker keyboard/fullscreen/focus regression is recorded separately below.

The separate `scripts/experiments/track-picker-ui.mjs` completed actual Chrome UI checks on ordinary insecure HTTP: initial keyboard focus/selection and return to the invoker, Escape/abort cleanup, and a 360-pixel dark viewport with dialog x=17 and width=326. Native Tab could visit browser toolbar chrome but did not focus the underlying page. A fullscreen VIDEO remained fullscreen while the dialog was used and a track was selected. Computed font/theme tokens matched the injected UI styles; light, narrow-dark and fullscreen screenshots were inspected. `.workspace/qa/caption-track-picker-ui.json` records `completed:true`, no errors, keyboard selection/focus return, escape/abort and fullscreen video selection. This was source-bundled UI verification without translation/model inference.

The final `scripts/experiments/native-tracks-real-model.mjs` completed against the installed fixed extension on an ordinary nonlocalhost HTTP player with two external native WebVTT tracks and the actual cached HY-MT2 model. Initially neither disabled track was fetched. With global source French, the explicit export loaded only French VTT and produced `Bonjour.`/`你好。`, then restored both disabled modes. Selecting native English overrode that global French preference: its actual outgoing source hint was `en`, and the export contained only `Hello world.`/`你好，世界。`. With both native tracks showing, the production ambiguity dialog selected French for that export without changing either native mode. Passive request observation recorded `fr`/`en` source hints and opaque CSPRNG IDs; it did not replace translation responses.

The executing background matched the build, cache completeness was verified, and `.workspace/qa/native-tracks-real-model.json` records `completed:true` with no page errors. Per-language/picked VTT files and `native-tracks-real-model.png` are retained; the screenshot was inspected. Its final intentionally ambiguous player may display both original native streams while the preformatted section shows the actual isolated bilingual exports; the action does not persistently override player track selection. This was an explicitly seeded integration cache rather than a fresh-download check, and the menu action was debugger-dispatched after a trusted pointer context event. No authenticated service, complete provider acquisition list or ASR provenance is claimed.
