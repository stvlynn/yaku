## Findings and reference journeys

### Temporary editing is a page interaction

Both packaged default configurations set `enableEditTranslation` to false. The English locale contains enable/disable labels and `Temporary translation editing`; the current inspected More drawer uses the latter as a switch. The official changelog records adding temporary editing to the panel's More entry in version 1.4.12. This establishes the documented entry, not persistence semantics. [Official changelog](https://immersivetranslate.com/en/docs/CHANGELOG/?force=1#1412).

Static drawer behavior queries the content frame's current edit state on opening and sends an explicit boolean when the switch changes. The content controller stores the flag in a JavaScript `Map` memory backend, updates the active rendering context, and adds/removes `contenteditable` on existing `[data-imt-p]` nodes. Later translation rendering also checks the flag and enables editability on newly rendered output. The off branch removes editability; that branch does not restore earlier text. These are static operation facts, not a demonstrated typing/undo journey. Evidence: C offsets 180991, 2349334, 2933909, 2936562 and 4221240; P offsets 1880785 and 1883439.

The supported user-level reading is: translate a page, open More, enable temporary editing, edit a rendered translation, then turn editing off. The memory backend supports a document-lifetime interpretation rather than a durable preference. The runtime below confirms one same-document URL change and a full reload; BFCache and frame transitions remain untested. There is no demonstrated evidence that edited text updates a glossary, model cache, cloud record, downloaded document or later translation result. Merely seeing an editable DOM node does not establish any of those storage contracts.

### Translation Comparison is specifically context versus baseline

`enableContextDiffPreview` is also false in packaged defaults. Its English `contextDiffPreview` locale label is `Translation Comparison`. This must not be conflated with ordinary source/translation bilingual reading, comparison between translation providers, or an edit revision history.

The inspected AI-context control builds a link to the current page with `imt_context_preview=1` and `_immersive_translate_auto_translate=1`, when comparison information is available. Its surrounding UI includes service capability and membership checks. The source's preview helper recognizes the query flag or the configuration flag. In the article path, comparison dispatch runs a context-enabled translation and a baseline with context/terminology state removed; the baseline also disables its ordinary cache path. Results are paired by sentence identity, and rendering produces two adjacent translation panels. The contextual result highlights differences against the baseline; the baseline is shown separately. A provider-level flag path also contains with-context/without-context comparison. The two paths are not evidence of a universal multi-service comparison tool. Evidence: C offsets 153798, 1356417, 1679797, 2252502, 2337463, 2344114 and 2901762.

The corresponding journey is: enable eligible AI context, open its information/comparison link, inspect the contextual and baseline translations of the same article. No successful reference runtime comparison, entitlement result, cancellation behavior, cost accounting, missing-result display or edit-to-comparison interaction was captured. Locale labels alone do not prove those details.

### Current card sharing and historical page snapshots differ

The official history first described a public link for a bilingual translated page in 0.11.5, then changed the format to a page snapshot. Importantly, version **1.20.6 removed the Snapshot entry from the panel**. A historical sharing tutorial therefore cannot prove a snapshot button still exists in the inspected 1.34.2 panel. [Official changelog](https://immersivetranslate.com/en/docs/CHANGELOG/?force=1#1206-release-2025-08-11).

The current package instead contains an X-post bilingual-card adapter and quick entry. Eligibility checks require a recognized post URL and both original and translated text, without a translation error. The packaged general rule disables card sharing; actual site activation depends on applicable rules and was not observed. Generation builds an image using original/translated post text, author/media metadata and a QR destination. The inspected image preview has Save; a native/mobile bridge conditionally exposes Share. Desktop save uses a PNG download. Although locale data also defines Copy and Copy Base64, those strings do not prove corresponding buttons in this preview. Evidence: D `generalRule.shareCardRule`; C offsets 2753135, 3889707, 3894269 and 4213715.

Yaku's desktop implementation opens a local bilingual card preview from the page context menu on X post detail URLs. It identifies the original post by its timestamp permalink and reads the translation session's original text and currently displayed translation, including temporary edits and translation-only mode. The PNG includes the account, both texts and the canonical post URL. Its QR code encodes that URL directly using a local module matrix, with a four-module quiet zone. The card offers file sharing when the browser accepts the PNG payload through `canShare`, and calls `share` from the button interaction. [uqr encoder](https://github.com/unjs/uqr#encode) · [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)

The card collects the selected post's avatar and up to four attached photos from the recognized X image CDN paths. It uses anonymous CORS fetches and keeps each included photo's aspect ratio. An unavailable image is skipped so the text and QR remain exportable. [Canvas and cross-origin images](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image)

`scripts/experiments/post-card-product.mjs` exercised the content action directly on a synthetic X-shaped post with offline HY-MT2. It verified untranslated-post refusal, an edited translation in the preview and an 800-pixel-wide PNG download. Pixel checks confirmed the included avatar and photo and the absence of a photo whose CORS origin did not match. The blocked fixture uses an explicit nonmatching origin because Playwright can supply the request origin for intercepted responses with no CORS header. A separate decoder recovered `https://x.com/example/status/731` from the saved pixels. Chrome exposed the Share button, and a controlled share call verified the PNG file payload and silent cancellation. The OS share chooser and authenticated X markup and CDN responses remain to be verified.

The same menu action works on timelines. It consumes the article from a trusted right-click and derives the canonical URL from that article's own timestamp. On a post detail URL, the current permalink supplies the fallback. `post-card-product.mjs --timeline` translated two adjacent synthetic posts and used a real right-click on the second one. Its export contained the selected post and its edit, and the QR decoded to that post's URL. A repeated action without a new right-click was refused on the timeline. The test sends the registered content action directly after the pointer event.

The isolated, unsigned-in Chrome probe `scripts/experiments/post-card-live-probe.mjs` attempted a public NASA post and received `net::ERR_HTTP_RESPONSE_CODE_FAILURE` before post DOM or CDN inspection. The probe records the navigation result and does not use a user profile. This leaves live-site compatibility unverified. [Public probe target](https://x.com/NASA/status/2040175881360941184)

The QR destination builder contains an original-post URL in a web redirect parameter, not the edited translation text or a demonstrated uploaded snapshot. The inspected renderer uses a canvas, and asset preparation can fetch avatars/media with omitted credentials; base64 output does not prove a fully offline/no-network journey. Existing-translation extraction could include current rendered edits, but that effect was not verified. Evidence: C offsets 3883099, 3892900 and 3895742.

A whole-page HTML snapshot helper also remains in the package. It clones page content and selected styling, with configured removal selectors and optional iframe handling. Its inspected callers attach that HTML to diagnostic/feedback reports. Presence of this helper or the legacy empty `shareToDraft` shortcut is not proof of a current public snapshot-share command. ## Clean-room product contract

The following is a proposed independent contract, not a claim that every detail was observed in the reference. It contains user actions and outcomes only; it does not copy package code, UI artwork, selectors or private protocols.

| Journey             | User action and required outcome                                                                                                                                                                                                                                                     | Boundary                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Temporary editing   | Explicitly enable editing for the current reading session; clearly indicate the active state; change translation text while source content remains intact; disable editing without silently changing the current edited text. Newly translated paragraphs follow the current switch. | Turning this into durable translation memory, source editing or a cloud save is separate work and must not be implied.                                         |
| Edit lifecycle      | Preserve a clear distinction between original source, generated translation and user-edited translation. Copy/export should state and use the currently displayed result when offered. Restore returns to source; retranslation must not silently masquerade as retaining edits.     | A persistence/retranslation policy requires an explicit product decision and tests, because the reference evidence does not settle it.                         |
| Context comparison  | Label two genuine results of the same source/model/languages: the configured context/terminology result and a context-free baseline. Show actual textual differences and identify a failed/missing result rather than duplicating one output into both columns.                      | Source-versus-translation reading, edited-versus-generated comparison and provider comparison need distinct names; none alone reproduces `contextDiffPreview`. |
| Sharing an artifact | Make the payload concrete before the action: a PNG card, a local reading document or a hosted snapshot/link. An image embeds the displayed text; a link to the original page does not thereby preserve edits.                                                                        | Creating a public hosted copy is not the same action as local download. No upload, remote account or public URL is established by the local model requirement. |
| Safe rendering      | Edited text and model results remain data. Preserve source/inline relationships, link destinations, protected code/formulas and media ownership; reject malformed structure rather than rendering model-supplied HTML.                                                               | The native `contenteditable` fact is not permission to copy arbitrary pasted HTML or bypass the shared strict marker policy.                                   |

With the present single local HY-MT2 engine, a terminology/context ablation could be an honest comparison when both variants are actually generated. It should not be labeled multi-engine comparison, and it must not silently introduce a cloud service. A local export can provide a reviewable sharing artifact without claiming the removed historical hosted-snapshot workflow. These are product adaptations, not assertions of reference equivalence.

## Acceptance still required

1. Original-runtime IME, actual clipboard paste, undo/redo, detailed selection/focus behavior and protection of links/code during edits directed at those nodes. Whole-container typing is observed above and can modify source text.
2. Restore, target/service changes, SPA article DOM replacement, iframe and BFCache behavior; whether any translation cache is updated. Switch-off, popup reopen, visible dynamic paragraphs, same-DOM URL change and full reload are observed above within their stated limits.
3. A real eligible comparison with observed requests, result pairing, labels, differences, failure/cancellation behavior and evidence that the two outcomes are genuinely distinct computations.
4. An actual enabled X card path, preview/save/native sharing and its complete network/payload behavior, including whether current manual edits enter the exported image.
5. Any present public-snapshot workflow after panel removal, with explicit upload/retention/deletion semantics. Until observed, historical documentation and feedback snapshots are insufficient.

No original-extension comparison/share runtime outcome or end-to-end parity acceptance is claimed. The bounded temporary-editing runtime above must not be generalized to those separate workflows.

## Yaku implementation follow-up: current-page controls

The Popup header now exposes More reading controls through a small Base UI popover, alongside Settings. It contains only the implemented Temporary editing switch. The control is checked from the current document's authoritative state, rather than a preference or an optimistic local checkbox. Unknown state and an in-flight change disable it. An active-state indicator and accessible trigger name keep enabled editing discoverable after the popover closes. There is no extra settings page, persistent setting, explanatory caption or comparison placeholder.

`PopupPage` accepts `temporaryEditing?: boolean`, `temporaryEditingPending?: boolean`, `onTemporaryEditingChange(enabled)` and `onReadingControlsOpen()`. Opening More requests a fresh state through root orchestration; the page component only renders props and owns popover visibility. Base UI provides named dialog semantics, checked switch semantics, keyboard interaction, Escape/Close dismissal and focus return. Existing Sunbeam tokens and the shared Toggle are reused; Toggle's only primitive addition is optional disabled forwarding. Errors appear once, inside the open popover or in the normal Popup when closed. Reading-query recovery must clear its own stale error without discarding unrelated failures.

## Context comparison: bounded design proposal

The reference's comparison is a genuine context-enabled result paired with a separately computed baseline. Current Yaku page/document requests use `context` for structural marker instructions; selected-text Explain uses a surrounding sentence. These uses are not a prepared article-context translation workflow. Named/scoped glossaries are terminology rules, not full AI context. None justifies exposing a control labeled AI context comparison today.

A future page-context comparison should first prepare a real semantic context snapshot from the original reading content, with an explicit token-budget and untrusted-content contract. Formatting requirements must remain present in both requests. Semantic context needs its own request field, so baseline generation does not accidentally remove strict marker requirements. Merely setting today's mixed-purpose `context` field to undefined would change structure preservation as well as context and would be an invalid baseline.

After that workflow exists and is validated, More can expose Compare context for the current translated passage. A compact reading comparison can show With page context and Without page context adjacent to the same source snapshot. Both use the same model, source/target languages, generation parameters and manual glossary; only the specified semantic context treatment differs. A narrower terminology-only experiment can be labeled Compare terminology if separately implemented, but cannot be presented as full article-context parity. Bounded inspection of the reference baseline removes prepared context and automatic article terminology while retaining the manual glossary and title environment; it is not an all-terms-free or title-free baseline. [Article-context research](article-context.md) documents these scoped facts and separates raw title/nearby text, reviewed context and generated context as experiment arms.

Each result needs a separate request identity and actual generation. Identical results are valid; one output must not be duplicated to simulate the second. Show each pending, failed or cancelled result independently, and retry only against a still-valid source/settings/context snapshot. Close or source/language/context changes invalidate both outstanding requests. Comparison must not overwrite a user's temporary edit, and differences should be computed on plain semantic output rather than marker/HTML strings. Protected code/math and source-owned media follow the existing codec ownership rules. No multi-provider, cloud/account or public-sharing claim follows from a local paired ablation.

Yaku now offers **Compare page context** in Reading controls after page translation. It chooses the translated passage containing the current selection, then falls back to a passage in view. The dialog runs two fresh requests from the passage snapshot and displays both results alongside the original text. It preserves inline format instructions and manual terms across the pair. Closing cancels outstanding requests, and results invalidated by navigation, source replacement or settings changes are discarded. The page's displayed translation remains available for reading and editing. The comparison currently uses the title and neighboring source passages. Prepared themes and automatic terminology remain separate work.

The contextual result highlights added or replaced word segments. The Chinese fixture segments `银行` and `河岸` as complete words. A mixed prose/code fixture keeps `npm` and the unchanged wording between the command and number changes. Character segmentation was also checked and splits those words and numbers into individual characters. The dialog uses bounded word alignment and displays both complete results as plain text when the alignment would exceed its work budget.
